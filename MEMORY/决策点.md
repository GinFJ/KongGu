# 空谷项目决策点

## 记录格式

每条决策至少包含：

- 日期
- 决策
- 原因
- 替代方案
- 影响范围
- 状态
- 复核条件

---

## D-001 项目归属和名称解释

- 日期：2026-08-06
- 决策：空谷统一表述为青禾计划孵化的课表协作产品；“空”指空课表，“谷”承接青禾从禾苗成长为谷物的意象。
- 原因：保证产品归属和名称解释统一，避免脱离青禾计划自行扩展。
- 替代方案：不采用“空课汇聚成谷”等未经确认的解释。
- 影响范围：产品介绍、汇报材料、界面文案、README 和对外宣传。
- 状态：有效。
- 复核条件：用户明确调整产品归属或名称解释。

## D-002 核心产品范围

- 日期：2026-08-06
- 决策：核心范围限定为多人中方、英方课表汇总与可信空课生成。
- 原因：保持产品围绕学生组织排班的真实问题，不泛化为普通个人课表工具。
- 替代方案：云同步、报名、考勤、成员数据库等不进入默认范围。
- 影响范围：需求分析、路线图、架构和功能优先级。
- 状态：有效。
- 复核条件：用户明确扩大产品范围。

## D-003 离线与隐私原则

- 日期：2026-08-06
- 决策：长期坚持离线 Windows 交付和本地数据处理。
- 原因：课表包含个人信息，组织使用场景需要低门槛部署和隐私控制。
- 替代方案：未经授权不使用云端识别、运行时模型下载或隐式联网。
- 影响范围：依赖选择、OCR、日志、安装包和发布验证。
- 状态：有效。
- 复核条件：用户明确批准新的数据处理和部署方案。

## D-004 可信结果优先

- 日期：2026-08-06
- 决策：可信结果和完整责任链优先于功能数量、表面识别覆盖率和自动接受率。
- 原因：排班结果错误会直接影响组织安排，必须保证错误可见、结果可复核。
- 替代方案：不采用以隐藏异常换取更高自动接受率的做法。
- 影响范围：产品指标、质量门禁、界面状态和导出。
- 状态：有效。
- 复核条件：仅可补充指标，不降低可信要求。

## D-005 文本层优先

- 日期：2026-08-06
- 决策：PDF 优先使用文本层，文本不足时才使用本地 OCR 或视觉回退。
- 原因：减少识别误差、资源消耗和不必要的隐私风险。
- 替代方案：不默认对所有文件执行 OCR。
- 影响范围：解析流程、依赖、性能和质量校验。
- 状态：有效。
- 复核条件：真实样本证据表明其他顺序更可靠。

## D-006 修系统而非修单个结果

- 日期：2026-08-06
- 决策：出现错误时修复输入预检、解析器、配置、质量规则或回归体系，不手工修改单个 Excel 掩盖问题。
- 原因：单次修补无法复用，也会破坏来源和责任链。
- 替代方案：人工修正只能作为可追溯的复核步骤，并需重新计算受影响结果。
- 影响范围：问题处理、回归测试、导出和审计。
- 状态：有效。
- 复核条件：无。

## D-007 统一质量状态

- 日期：2026-08-06
- 决策：解析结果统一使用 `accepted / needs_review / blocked`。
- 原因：将正常、待复核和阻断问题清晰区分，支持质量门禁。
- 替代方案：不使用含义模糊的“成功 / 失败”二元状态覆盖全部场景。
- 影响范围：解析器、工作流、界面、导出和测试。
- 状态：有效。
- 复核条件：状态模型发生经验证的系统性调整。

## D-008 采用项目记忆系统

- 日期：2026-08-06
- 决策：使用 `MEMORY.md`、`决策点.md`、`待办.md` 和 `事实.md` 分离记录动态信息。
- 原因：避免长期规则、事实、决策和待办混放，保证项目连续协作。
- 替代方案：不把当前版本、测试数字和短期待办写入 `AGENTS.md`。
- 影响范围：所有长期协作、项目交接和状态维护。
- 状态：有效。
- 复核条件：项目文件治理方式整体调整。

## D-009 治理基础包落地与参考库位置

- 日期：2026-08-08
- 决策：以「空谷优化包」为规范参考落地治理层文件，不逐字照搬；参考资料库固定为 `resources/reference/`；本次只改文件，不做 Git 提交。
- 原因：优化包是治理模板而非成品；仓库顶层 `resources/` 已被运行时 OCR 资源占用，Windows 不区分大小写，不能另建顶层 `Resources/`；用户确认只改文件不提交。
- 替代方案：顶层 `Resources/`（需重命名运行时目录并改动代码、配置、清单和测试，风险高）；逐字照搬包内结构（与仓库现状脱节）。
- 影响范围：AGENTS.md、MEMORY/、参考资料库、docs/ 与 tests/ 配套文档、README。
- 状态：有效。
- 复核条件：用户调整目录约定或提交策略。

## D-010 版本跟随变更升级

- 日期：2026-08-08
- 决策：任何进入正式交付的变更（含文档、治理与记忆文件）完成后，版本标识随变更升级并同步全部版本引用；本次 README 全中文优化由 0.3.0 升至 0.3.1。
- 原因：避免版本标识与实际内容脱节，保证 README 徽章、Cargo/package 与交付物保持一致。
- 替代方案：仅在正式发布时统一升版（版本标识会长期滞后于实际内容）。
- 影响范围：`package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json`、README、`MEMORY/` 与 `docs/变更记录.md`。
- 状态：有效。
- 复核条件：用户调整版本策略，或项目进入正式发布流程。
