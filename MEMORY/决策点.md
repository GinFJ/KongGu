# 空谷项目决策点

## D-001 项目归属和名称解释

- 日期：2026-08-06
- 决策：空谷统一表述为青禾计划孵化的课表协作产品；“空”指空课表，“谷”承接青禾从禾苗成长为谷物的意象。
- 原因：保证产品归属和名称解释统一，避免脱离青禾计划自行扩展。
- 替代方案：不采用“空课汇聚成谷”等未经确认的解释。
- 影响范围：产品介绍、汇报材料、界面文案、README 和对外宣传。
- 状态：有效。
- 复核条件：用户明确调整产品归属或名称解释。

## D-002 核心产品范围

- 日期：2026-08-06
- 决策：核心范围限定为多人中方、英方课表汇总与可信空课生成。
- 原因：保持产品围绕学生组织排班的真实问题，不泛化为普通个人课表工具。
- 替代方案：云同步、报名、考勤、成员数据库等不进入默认范围。
- 影响范围：需求分析、路线图、架构和功能优先级。
- 状态：有效。
- 复核条件：用户明确扩大产品范围。

## D-003 离线与隐私原则

- 日期：2026-08-06
- 决策：长期坚持离线 Windows 交付和本地数据处理。
- 原因：课表包含个人信息，组织使用场景需要低门槛部署和隐私控制。
- 替代方案：未经授权不使用云端识别、运行时模型下载或隐式联网。
- 影响范围：依赖选择、OCR、日志、安装包和发布验证。
- 状态：有效。
- 复核条件：用户明确批准新的数据处理和部署方案。

## D-004 可信结果优先

- 日期：2026-08-06
- 决策：可信结果和完整责任链优先于功能数量、表面识别覆盖率和自动接受率。
- 原因：排班结果错误会直接影响组织安排，必须保证错误可见、结果可复核。
- 替代方案：不采用以隐藏异常换取更高自动接受率的做法。
- 影响范围：产品指标、质量门禁、界面状态和导出。
- 状态：有效。
- 复核条件：仅可补充指标，不降低可信要求。

## D-005 文本层优先

- 日期：2026-08-06
- 决策：PDF 优先使用文本层，文本不足时才使用本地 OCR 或视觉回退。
- 原因：减少识别误差、资源消耗和不必要的隐私风险。
- 替代方案：不默认对所有文件执行 OCR。
- 影响范围：解析流程、依赖、性能和质量校验。
- 状态：有效。
- 复核条件：真实样本证据表明其他顺序更可靠。

## D-006 修系统而非修单个结果

- 日期：2026-08-06
- 决策：出现错误时修复输入预检、解析器、配置、质量规则或回归体系，不手工修改单个 Excel 掩盖问题。
- 原因：单次修补无法复用，也会破坏来源和责任链。
- 替代方案：人工修正只能作为可追溯的复核步骤，并需重新计算受影响结果。
- 影响范围：问题处理、回归测试、导出和审计。
- 状态：有效。
- 复核条件：无。

## D-012 PDF Inspector 先旁路诊断后参与路由

- 日期：2026-08-09
- 决策：固定使用 Firecrawl Python binding `pdf-inspector==0.2.6`，先在 Python sidecar 中生成隐私安全的 PDF 结构诊断并展示到复核页；当前不替换 PyMuPDF、不改变课程块、不直接改变质量门禁，也不启用逐页 OCR 路由。
- 原因：其逐页 OCR 原因、字体编码和复杂版式信号契合空谷可信预检，但官方通用 PDF 基准不能证明中英方课表准确率。
- 替代方案：直接替换 PyMuPDF、在 WebView 使用 Node N-API、首轮接入 WASM 或嵌入 Streamlit，均会扩大架构和打包风险。
- 影响范围：`core/pdf_inspection.py`、Python sidecar、工作流持久化、PDF 复核页、依赖与 PyInstaller 打包。
- 状态：已提交并验证（功能提交 `e7ab4ef`）；针对性测试、前端构建、sidecar 冻结和 70 份真实样本的页级文本层判断已验证，课程块人工真值和发布级验证未完成。
- 复核条件：脱敏中英方、扫描型、混合型和乱码文本层样本完成真值对账后，再决定是否让逐页判断参与 OCR 路由。

## D-013 阿谷作为空谷虚拟形象

- 日期：2026-08-11
- 决策：空谷虚拟形象定名为“阿谷”，采用非人谷物精灵造型；双叶冠、透明青心种仁和圆润谷粒身体是不可替换的核心识别，角色表达统一为“青心如禾，向阳而生”。
- 原因：把空谷与青禾计划的成长意象转化为稳定、可复用的视觉角色，同时避免把“谷”误解为山谷或把产品拟人成通用 AI 助手。
- 替代方案：不采用人类、动物、机器人、普通米粒或山谷地形形象；不把阿谷收窄为隐私守护者。
- 影响范围：桌面端启动与积极状态、README、应用图标、汇报封面、宣传材料和后续角色动作。
- 状态：有效；角色 1.0 资产和规范已在 0.4.2 提交 `84bebd7` 中验证并落地，尚未发布。
- 复核条件：用户明确调整角色定位，或现有识别特征在小尺寸、印刷或无障碍场景中无法满足使用要求。

## D-018 OCR 模型使用 ASCII 兼容运行目录

- 日期：2026-09-13
- 决策：Windows 上保留原有 `%LOCALAPPDATA%\Konggu` 用户数据目录，不迁移学期设置、记录和缓存；OCR 模型运行目录单独选择 ASCII 路径。显式配置的 ASCII `KONGGU_OCR_MODEL_DIR` 优先；否则应用数据路径为 ASCII 时继续使用原 `ocr_models`，应用数据路径含非 ASCII 字符时自动改用 `%PROGRAMDATA%\Konggu\ocr_models`，无法使用时尝试 `%PUBLIC%`。资源状态、自动修复和 OCR 初始化必须使用同一目录。
- 原因：Paddle 的 Windows C++ 推理层无法可靠读取中文模型路径，中文用户名会导致模型初始化失败；直接把全部应用数据迁移到 ProgramData 会扩大用户数据迁移和 ACL 风险。
- 替代方案：要求用户手动设置环境变量、复制到 `C:\KongguDiag` 等临时目录，或依赖 8.3 短路径。这些方案依赖人工配置、临时目录或系统设置，不作为正式交付主路径。
- 影响范围：`app/offline_resources.py`、OCR 运行时环境、资源状态与修复、界面错误说明、回归测试、README、版本和发布验收。
- 状态：已实现并通过当前工作区回归；0.5.4 安装包和中英文用户名真实安装环境验收尚未完成。
- 复核条件：Paddle 后续版本原生支持非 ASCII 路径且完成回归，或 ProgramData 在普通用户、多账户和只读 ACL 场景中出现不可接受问题。

## D-019 来源冲突阻断与修正后重算

- 日期：2026-10-16
- 决策：已选择的文件缺失或不可读、不同目录存在同名 PDF 时保留可处理文件的预览，但整批标记 `blocked`，禁止正式导出；原文路径按文件名和内容哈希关联。人工修正节次、周次或成员后重算占用、成员、预览、质量状态和问题记录。
- 原因：静默跳过或按文件名覆盖来源会让排班结果缺人、原文核对错位；只修改课程块而不更新派生结果会产生错误空闲名单。
- 替代方案：自动选择同名文件、继续跳过缺失文件或只局部刷新界面；这些做法无法证明来源与结果一致。
- 影响范围：输入预检、课程块契约、人工修正、持久化、导出门禁和签名构建错误传播；解析器签名升至 35，旧缓存和旧修正重新评估。
- 状态：源码与合成回归已验证；仓库外 35 组配对完成流程与质量状态回归，0.5.5 离线安装包已构建并通过静态门禁；功能提交 `d8b81e5` 已推送，未签名安装包作为 `v0.5.5-rc.1` 预发布资产上传。课程人工真值、实际安装和物理断网仍未验证，正式发布验收未完成。

## D-021 结果不静默截断与缓存按引擎/模型校验

- 日期：2026-10-18
- 决策：界面不得静默丢弃解析结果，共同空闲按每页 800 行显式分页并显示总时段数与页码；OCR 文字缓存同时校验 OCR 引擎与模型，解析器签名仍只覆盖解析规则与配置；旧缓存无元数据时按当前引擎兼容并补写元数据。
- 原因：静默截断会让用户按不完整结果排班；OCR 文字只依赖源文件与 OCR 引擎/模型，不依赖解析规则，把完整解析器签名压到文字缓存上会让每次规则调整都无谓重跑全量 OCR。
- 替代方案：直接渲染全部 1600 行以上（WebView2 渲染压力大且没有分页语义）；把解析器签名加入 OCR 文字缓存键（会作废 OCR 缓存并触发长时间重跑）。
- 影响范围：`src/main.ts`、`src/reviewView.ts`、`core/schedule_core.py`、前端契约与 OCR 缓存回归。
- 状态：源码版本升至 0.5.8，工作区已验证（`200 passed`、`tsc --noEmit`、Vite 构建），未提交、未构建安装包。
- 复核条件：结果行数增长到需要虚拟滚动，或 OCR 引擎/模型切换流程改变。

## D-023 解析器签名覆盖生效学期设置

- 日期：2026-10-18
- 决策：`ParserSignature` 增加 `calendar_start` 与 `teaching_weeks` 两个字段，取值顺序与运行时一致（环境变量 → `config/school_calendar.json` → 默认值）；`PARSER_VERSION` 由 38 升至 39。解析缓存路径与缓存校验、人工修正的签名比对都因此对学期设置变化敏感。
- 原因：用户可在界面修改“第 1 周周一”和教学周数，这两个值决定课程日期、周次和跨年选年。原签名只覆盖 `config/` 文件，改学期后命中旧学期解析缓存与旧修正，静默产出错误周次；这是审计中实测复现的缺陷。
- 替代方案：每次改设置时单独清理解析缓存与修正（需要额外生命周期与失败处理）；或把学期设置写回 `config/school_calendar.json`（会混入用户数据目录与随包配置）。
- 影响范围：`core/signature.py`、`core/schedule_core.py`、`app/services/calendar_settings.py`、解析缓存、人工修正复用、回归测试与后续发布。
