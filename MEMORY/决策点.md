# 空谷项目决策点

## 记录格式

每条决策至少包含：

- 日期
- 决策
- 原因
- 替代方案
- 影响范围
- 状态
- 复核条件

---

## D-001 项目归属和名称解释

- 日期：2026-08-06
- 决策：空谷统一表述为青禾计划孵化的课表协作产品；“空”指空课表，“谷”承接青禾从禾苗成长为谷物的意象。
- 原因：保证产品归属和名称解释统一，避免脱离青禾计划自行扩展。
- 替代方案：不采用“空课汇聚成谷”等未经确认的解释。
- 影响范围：产品介绍、汇报材料、界面文案、README 和对外宣传。
- 状态：有效。
- 复核条件：用户明确调整产品归属或名称解释。

## D-002 核心产品范围

- 日期：2026-08-06
- 决策：核心范围限定为多人中方、英方课表汇总与可信空课生成。
- 原因：保持产品围绕学生组织排班的真实问题，不泛化为普通个人课表工具。
- 替代方案：云同步、报名、考勤、成员数据库等不进入默认范围。
- 影响范围：需求分析、路线图、架构和功能优先级。
- 状态：有效。
- 复核条件：用户明确扩大产品范围。

## D-003 离线与隐私原则

- 日期：2026-08-06
- 决策：长期坚持离线 Windows 交付和本地数据处理。
- 原因：课表包含个人信息，组织使用场景需要低门槛部署和隐私控制。
- 替代方案：未经授权不使用云端识别、运行时模型下载或隐式联网。
- 影响范围：依赖选择、OCR、日志、安装包和发布验证。
- 状态：有效。
- 复核条件：用户明确批准新的数据处理和部署方案。

## D-004 可信结果优先

- 日期：2026-08-06
- 决策：可信结果和完整责任链优先于功能数量、表面识别覆盖率和自动接受率。
- 原因：排班结果错误会直接影响组织安排，必须保证错误可见、结果可复核。
- 替代方案：不采用以隐藏异常换取更高自动接受率的做法。
- 影响范围：产品指标、质量门禁、界面状态和导出。
- 状态：有效。
- 复核条件：仅可补充指标，不降低可信要求。

## D-005 文本层优先

- 日期：2026-08-06
- 决策：PDF 优先使用文本层，文本不足时才使用本地 OCR 或视觉回退。
- 原因：减少识别误差、资源消耗和不必要的隐私风险。
- 替代方案：不默认对所有文件执行 OCR。
- 影响范围：解析流程、依赖、性能和质量校验。
- 状态：有效。
- 复核条件：真实样本证据表明其他顺序更可靠。

## D-006 修系统而非修单个结果

- 日期：2026-08-06
- 决策：出现错误时修复输入预检、解析器、配置、质量规则或回归体系，不手工修改单个 Excel 掩盖问题。
- 原因：单次修补无法复用，也会破坏来源和责任链。
- 替代方案：人工修正只能作为可追溯的复核步骤，并需重新计算受影响结果。
- 影响范围：问题处理、回归测试、导出和审计。
- 状态：有效。
- 复核条件：无。

## D-007 统一质量状态

- 日期：2026-08-06
- 决策：解析结果统一使用 `accepted / needs_review / blocked`。
- 原因：将正常、待复核和阻断问题清晰区分，支持质量门禁。
- 替代方案：不使用含义模糊的“成功 / 失败”二元状态覆盖全部场景。
- 影响范围：解析器、工作流、界面、导出和测试。
- 状态：有效。
- 复核条件：状态模型发生经验证的系统性调整。

## D-008 采用项目记忆系统

- 日期：2026-08-06
- 决策：使用 `MEMORY.md`、`决策点.md`、`待办.md` 和 `事实.md` 分离记录动态信息。
- 原因：避免长期规则、事实、决策和待办混放，保证项目连续协作。
- 替代方案：不把当前版本、测试数字和短期待办写入 `AGENTS.md`。
- 影响范围：所有长期协作、项目交接和状态维护。
- 状态：有效。
- 复核条件：项目文件治理方式整体调整。

## D-009 治理基础包落地与参考库位置

- 日期：2026-08-08
- 决策：以「空谷优化包」为规范参考落地治理层文件，不逐字照搬；参考资料库固定为 `resources/reference/`；本次只改文件，不做 Git 提交。
- 原因：优化包是治理模板而非成品；仓库顶层 `resources/` 已被运行时 OCR 资源占用，Windows 不区分大小写，不能另建顶层 `Resources/`；用户确认只改文件不提交。
- 替代方案：顶层 `Resources/`（需重命名运行时目录并改动代码、配置、清单和测试，风险高）；逐字照搬包内结构（与仓库现状脱节）。
- 影响范围：AGENTS.md、MEMORY/、参考资料库、docs/ 与 tests/ 配套文档、README。
- 状态：有效。
- 复核条件：用户调整目录约定或提交策略。

## D-012 PDF Inspector 先旁路诊断后参与路由

- 日期：2026-08-09
- 决策：固定使用 Firecrawl Python binding `pdf-inspector==0.2.6`，先在 Python sidecar 中生成隐私安全的 PDF 结构诊断并展示到复核页；当前不替换 PyMuPDF、不改变课程块、不直接改变质量门禁，也不启用逐页 OCR 路由。
- 原因：其逐页 OCR 原因、字体编码和复杂版式信号契合空谷可信预检，但官方通用 PDF 基准不能证明中英方课表准确率。
- 替代方案：直接替换 PyMuPDF、在 WebView 使用 Node N-API、首轮接入 WASM 或嵌入 Streamlit，均会扩大架构和打包风险。
- 影响范围：`core/pdf_inspection.py`、Python sidecar、工作流持久化、PDF 复核页、依赖与 PyInstaller 打包。
- 状态：已提交并验证（功能提交 `e7ab4ef`）；针对性测试、前端构建、sidecar 冻结和 70 份真实样本的页级文本层判断已验证，课程块人工真值和发布级验证未完成。
- 复核条件：脱敏中英方、扫描型、混合型和乱码文本层样本完成真值对账后，再决定是否让逐页判断参与 OCR 路由。

## D-013 阿谷作为空谷虚拟形象

- 日期：2026-08-11
- 决策：空谷虚拟形象定名为“阿谷”，采用非人谷物精灵造型；双叶冠、透明青心种仁和圆润谷粒身体是不可替换的核心识别，角色表达统一为“青心如禾，向阳而生”。
- 原因：把空谷与青禾计划的成长意象转化为稳定、可复用的视觉角色，同时避免把“谷”误解为山谷或把产品拟人成通用 AI 助手。
- 替代方案：不采用人类、动物、机器人、普通米粒或山谷地形形象；不把阿谷收窄为隐私守护者。
- 影响范围：桌面端启动与积极状态、README、应用图标、汇报封面、宣传材料和后续角色动作。
- 状态：有效；角色 1.0 资产和规范已在 0.4.2 提交 `84bebd7` 中验证并落地，尚未发布。
- 复核条件：用户明确调整角色定位，或现有识别特征在小尺寸、印刷或无障碍场景中无法满足使用要求。

## D-014 阿谷采用状态驱动的有限姿态动画

- 日期：2026-08-11
- 决策：桌面端复用已确认的标准、动态和完成立绘，通过独立 `aguMotion` 组件组合姿态切换、压缩伸展、重心变化、接触阴影、青心光效与粒子收势；欢迎、处理中和可信完成使用不同动作，减少动态效果时退化为静态姿态。
- 原因：现有源图是扁平位图，无法诚实地实现叶冠、四肢和表情的独立骨骼绑定；有限姿态动画可以在不重画角色、不引入运行时依赖和不扩大离线包的前提下，消除单纯上下浮动感。
- 替代方案：不采用持续整体浮动；当前不引入视频、GIF、Lottie、Spine 或运行时生成模型，也不伪称为分层骨骼动画。
- 影响范围：欢迎空状态、课表处理状态、可信完成状态、动效可访问性、品牌视觉规范和后续分层角色资产规划。
- 状态：在研；132 项 Python 测试、TypeScript、Vite、konggu v0.5.0 Cargo 和浏览器欢迎状态检查通过，处理中、完成和减少动态效果的真实 Tauri 逐态与发布级安装验证尚待完成。
- 复核条件：获得经确认的分层角色源文件，或有限姿态切换在真实桌面端出现明显重影、裁切或性能问题。

## D-015 用户界面使用任务与结果语言

- 日期：2026-08-11
- 决策：底层继续使用质量状态、解析签名、任务记录和审计事件保证结果可追溯；普通用户界面不直接展示这些工程术语，统一围绕“导入课表—生成空课表—处理问题—原文核对—导出空课表”表达。品牌标题使用已确认口号“青心如禾，向阳而生”，操作说明直接写用户动作和结果，不使用“从共同空课时间出发”“找到可以发生的时间”等含义模糊的宣传句。
- 原因：内部治理概念能够约束系统，但不能替代用户对当前结果、下一步操作和产物的理解；“门禁、签名、任务 ID、课程块、审计轨迹”等词会增加使用门槛。
- 替代方案：不删除底层质量控制和追溯字段；不把内部字段名直接翻译后继续堆在主界面；开发诊断信息保留在代码、持久化、测试和技术文档中。
- 影响范围：桌面端主流程、状态提示、结果表头、问题处理、原文核对、README 与界面回归测试。
- 状态：在研；0.5.0 工作区已完成用户语言改写、流畅界面改造、132 项 Python 回归、TypeScript、前端构建、Cargo 和 1280×720 / 1080×820 浏览器检查，尚未提交或构建当前源码对应安装包。
- 复核条件：真实使用者仍无法根据界面独立完成导入、核对和导出，或调试信息不足以支持问题定位。

## D-016 稳定外壳与空谷品牌化流畅界面

- 日期：2026-08-11
- 决策：桌面端保留空谷墨绿、纸张感和阿谷形象，以一次挂载的稳定外壳承载局部状态更新；高频进度按动画帧合并，标签面板、PDF 复核和课程周视图不因无关状态变化反复销毁，并统一使用圆润层级、轻透明材质、即时按压反馈和无回弹的短时过渡。
- 原因：此前每次进度、标签或确认操作都会整体替换 `app.innerHTML`，导致焦点、滚动、富视图实例和阿谷动画缺乏连续性；只叠加更多关键帧不能修复生命周期问题。
- 替代方案：不引入 Motion、Framer Motion 或新的在线依赖；不复制 macOS 红黄绿窗口控件；不把角色动画放进阻断问题和严肃证据区。
- 影响范围：`src/main.ts`、`src/reviewView.ts`、`src/uiMotion.ts`、`src/styles.css`、TypeScript 目标、前端回归和桌面界面验收。
- 状态：在研、代码与浏览器基线已验证；132 项 Python 测试、TypeScript、Vite、Cargo、1280×720 / 1080×820 浏览器边界与交互通过，真实 Tauri 富视图逐态和当前源码安装包尚未验证。
- 复核条件：局部更新导致状态不同步，PDF/日历保留错误，WebView2 对透明材质兼容不佳，或真实桌面性能记录出现新增长任务时重新评估。

## D-017 启动自动初始化离线识别资源

- 日期：2026-08-14
- 决策：空谷启动时自动执行本地离线资源校验与修复；只在资源缺失或校验失败时复制，正常资源不重复复制；界面保留手动修复按钮作为异常兜底。
- 原因：首次启动、更新或本机资源被清理后，不应把正常的本地初始化责任交给普通使用者频繁点击按钮；同时必须保留资源完整性校验和离线边界。
- 替代方案：继续只查询状态并要求用户手动修复；或运行时联网下载模型，后者违反空谷的离线与隐私原则。
- 影响范围：启动流程、本地资源修复、识别状态提示、README、回归测试和后续安装包验收。
- 状态：源码、回归和包含本次改动的安装包均已构建并通过静态门禁；真实安装验收仍未完成。
- 复核条件：自动修复造成启动时间明显增加、资源复制失败率上升，或真实安装验收发现打包资源缺失。
