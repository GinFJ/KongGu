# 本机课表历史 · 空谷 0.14.0

本机交付目录为 `build/candidates/0.14.0-local-history/`。免安装版运行其中的 `portable/konggu.exe`，安装版运行 `Konggu_0.14.0_x64-setup.exe`。源码和测试的运行方法见[项目 README](../README.md)。

## 退出后继续制作

在桌面版生成合表后，可以直接退出。下次在同一台电脑、同一 Windows 用户和空谷工作区打开软件，“本机课表记录”会列出已生成的各批课表。这个功能可以离线使用，无需登录。

1. 根据日期范围、原件文件名、文件数和更新时间找到那一批，点“打开”。空谷会载入课表和已保存的核验进度，可以继续修改、核验和导出。
2. 要开始另一批，点“新建合表”。如果上次只选了原件或日期，还可以点“继续上次草稿”。替换未生成的草稿前会提示确认。
3. 制作期间可从左侧“本机课表记录”切换批次或查看空间。首次使用时直接进入制表界面。

新生成的课表持续保存在本机。升级前仍保存在本机的旧批次也会列出，打开一次即可按新规则保留。旧版已过期清理的批次无法恢复。未生成的草稿保留 30 天。打开已生成的课表可以查看保存的结果；需要翻看 PDF 原页时，如果原件搬了位置、未记住或位置已过期，点“关联原件”重新选择对应 PDF 即可。启用“记住原件位置”时，位置单独保存 30 天。

## 查看和清理空间

在“本机课表记录”底部看“本机存储”。点“刷新”可重新读取数值。

| 界面项目 | 显示什么 | 点击清除后的结果 |
| --- | --- | --- |
| 识别缓存 | 可清除的处理文件大小和数量 | “清除识别缓存”释放这部分空间，保留课表和核验进度。下次识别同一份原件时可能需要重新处理。 |
| 记录数据库 | 当前工作区的数据库文件总大小及已生成批次数 | “清除全部本机记录”需要再次确认，会同时清除本工作区的课表记录、草稿、核验修正和识别缓存。 |

两种清理都会保留原始 PDF 和已导出的 Excel。清除全部记录后，列表显示 0 批；空数据库本身仍占少量空间。

## 验证记录

在隔离的本机数据目录中，用合成 PDF 生成了两批日期不同的课表，并确认了一名成员。完全退出桌面服务后重开，能够依次打开两批。识别缓存清至 0 B、0 个文件后，批次数仍为 2，已确认成员和日期仍可恢复。从历史课表导出的 Excel 已重新打开核对。确认清除全部记录并再次重启后，列表为空，原始 PDF 和已导出的 Excel 仍在。

在 1280 × 820 和 1080 × 720 两种窗口下验证了历史选择、新建及继续草稿，并验证了取消清理的流程。完整 Python 回归 796 项、Node 回归 15 项通过。

Windows x64 安装包为 539,557,150 字节，SHA-256 为 `3e2a88c396f6a4e2d624eb0bb8ce3b01a8b5187a4d18ae3def27d061f3415dc4`。安装包和免安装主程序的文件版本均为 0.14.0。本地构建使用基于 `b57a0c5` 的工作区。用包内识别程序重复了三次进程启动、历史恢复、清理和 Excel 导出测试，也验证了全新数据目录中的离线 OCR。

在安装包解出的 Windows 桌面程序中又连续启动三次，每次正常退出时，主程序和识别进程均已结束。重开时可以选择较早的课表。清理前窗口显示“4.1 KB · 2 个文件”，清理后为“0 B · 0 个文件”。再次退出重开，历史课表仍显示已核验 1/1，新建也保留两批历史。本机交付目录中的 `native-history-verification.json` 保存了这次测试的逐次结果。
