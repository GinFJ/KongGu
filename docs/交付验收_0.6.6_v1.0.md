# 空谷 0.6.6 识别修复与交付验收

记录日期：2026-11-13。解析签名 66。当前为本地未提交的交付候选，不是 GitHub Release。基底提交为 `ef6df1341e6abebf7db6567542db3d8b96db1942`；本轮差异与产物指纹另行记录。

## 修复的问题

1. 英方跨页课程简称漏识别后，旧规则会丢掉班组和教室，整格没有课程种子，造成错误空闲。现在先按实际边框确定日期行、单节及合并格；非空格保留占用，名称不完整时显示具体页码、日期、节次和复核提示。
2. 页眉曾混入课程，续页边界曾延伸到标题区域。现在使用表格可见边界，并排除网页标题和页眉。
3. 缩放后浅色细边框曾导致整行判定失败。横竖线使用局部对比度，尺度依据实际格宽和行距。
4. 一个其他周次的日期被 OCR 破坏后，整行课程消失。增加同一周两个有效日期、星期和行距的共同校验；不改写可读但矛盾的日期。
5. 悬浮详情遮挡表格、无编号午间格有课但缺时间映射，会记录绑定来源哈希及解析签名的阻断证据；缓存命中、复核和恢复任务不得丢掉问题。
6. 原件的日期筛选范围不一定等于整个学期。现在依据原页日期行及 Start/End 条件限制可生成空课的完整工作周，防止查询结束后的空白行被当作无课；复核、重新载入和导出都保留这个限制。
7. 单批上限由 32 份提高至 128 份，支持本次组织的完整课表批次。逐文件串行处理，原 200 MiB 总量及 1000 页上限保持。
8. 原生验收发现未嵌入中文映射的 PDF 能被解析，但原文核对页空白。将现有 PDF.js 的 185 个 CMap/标准字体资源（1948053 字节，未压缩）随前端打包，开发环境和安装态都从本机读取，构建门禁校验内容哈希。没有修改系统字体或放宽安全策略。

没有新增运行时依赖或模型。运行仍使用本地 PDF 文本层、包内 PaddleOCR 和版式规则。本轮 AI 视觉对照属于验收过程，不是需要每周在线代改结果的运行步骤。
