# 空谷 0.12.0 · 用账号接着制表

制表人用自己的账号保存整批课表。例如办公室负责人导入了 20 人的中方和英方课表，换电脑登录后可以打开这一批，看到全组名单、课程、空课结果、人工修正及核验进度。

## 第一次保存

1. 打开空谷，点左侧「登录 / 注册」，填写管理员提供的服务地址并登录。首次使用可点「注册并登录」。
2. 在账号工作区导入并生成课表。打开「云端批次」，给这批资料起名，点「保存当前批次到云端」。
3. 如果已经在本机模式做好课表，登录后展开「从本机模式转入已有批次」，填写名称并点「复制到我的云端」。确认后可从列表打开。原本机工作区仍可继续使用。

云端保存成员、课程、原文件名、内容标识、学期设置及核验修正。PDF 原件、原件路径和整页 OCR 文本留在本机。每次修改后再次点击保存，另一台电脑即可打开最新版。

## 换电脑继续做

1. 在第二台电脑使用同一版本的空谷，填写相同服务地址，登录相同账号。
2. 在「我的云端批次」中点对应批次的「打开」。可以直接查集体空课、修改课程。先前已完成核验、符合导出条件的批次可以直接导出 Excel。
3. 要对照 PDF 新增核验确认，或需要重新识别时，点「关联原件」并选择同一批 PDF。空谷会检查文件名和内容。这一步保留已恢复的核验进度。

不同账号分别管理自己的批次。若另一台设备已更新，空谷会提示冲突。可先将本机修改「另存为新批次」，或打开云端最新版。退出账号后回到原本机工作区。清除本机记录只影响当前本地工作区。

## 服务地址

实际跨机使用需要两台电脑都能访问的同一个 HTTPS 服务。管理员可在自己的服务器部署配套服务。只想在一台 Windows 电脑体验注册、切换账号和批次保存，可运行本机试用启动器，在软件里填写 `http://127.0.0.1:8765`。这个地址只连接当前电脑。[本机启动器](../cloud_service/start-local.cmd) · [部署与备份说明](../cloud_service/README.md)

2026-11-26，两个独立桌面识别进程通过真实 HTTP 连接本机账号服务，使用不同的数据目录和合成 PDF。验证了本机批次转入账号、设备切换、课程修改、关联原件核验、Excel 导出、版本冲突、账号隔离和退出后恢复原本机工作区。服务端另验并发保存、服务重启后数据保留和令牌失效。部门课表恢复前后的导出逐单元格一致。[桌面到服务端测试](../tests/test_cloud_desktop_session.py) · [批次恢复测试](../tests/test_cloud_batch.py) · [服务端测试](../cloud_service/test_http.py)

本轮仅使用合成课表测试云存储。正式服务器部署与两台实体电脑上的互联网验收待完成。

Chrome 在 1280×820 和 1080×720 两个尺寸完成界面联调，桌面通信经测试桥连接真实识别进程及 HTTP 账号服务，覆盖登录、转入本机批次、跨工作区打开、冲突另存和退出。最终针对文件选择框延迟返回、冲突提示做了两项模拟响应复测。TypeScript 检查和 Vite 生产构建通过。

本轮桌面 Python 全量回归 766 项通过，其中跨设备测试实际启动了两份本版冻结识别程序，读取不同数据目录。账号服务真实 HTTP 集成测试 4 项、现有 Node 回归 10 项通过。本机试用启动器已在临时数据库完成启动和合成账号注册。

从最终安装器解包后，实际 Windows WebView2 窗口和打包识别程序连接服务 ZIP 解压启动的账号服务，完成合成账号注册、打开空批次列表、退出、重新登录及刷新。验收使用独立 Windows 桌面与全新数据目录。

本版 Windows 候选采用默认构建配置，未内置旧私有试用包的 AI 密钥。可选 AI 原页核对需要另行配置密钥，制表和账号存储不依赖该密钥。
