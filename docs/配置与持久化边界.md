# 配置与持久化边界

核对日期：2026-11-15。依据当前源码检索与现有回归，说明配置文件实际参与哪一步；不将打包存在或签名变化解释成规则已经生效。当前版本与交付状态见 [项目总览](../MEMORY/MEMORY.md)。

## 配置的实际消费位置

| 文件 | 当前消费者 | 修改效果与限制 |
|---|---|---|
| `config/school_calendar.json` | `core/schedule_core.py`、`core/signature.py` | 解析器在环境变量未提供有效值时读取学期起点与教学周数。桌面服务先载入用户学期设置并写入环境变量，因此用户设置优先；首次桌面设置使用代码默认值。`special_adjustments` 尚未参与补课/调课计算。 |
| `config/period_time.json` | 联合解析签名、离线资源打包与校验、配置测试 | 当前节次时间来自 `schedule_core.default_timetable()` 及午间常量，未从本 JSON 动态载入。核对时 13 个节次时间一致；仅修改 JSON 会改变签名，不能直接改变实际时间映射。 |
| `config/timetable_layout_profiles.json` | 联合解析签名、离线资源打包与校验 | profile 检测和路由在 `schedule_core` 的代码分支中。文件内的固定 21 周、旧样本日期及 `confidence.auto_accept` 等是早期描述，不是现行阈值，也不会自动放行结果；实际边界见 [识别规则](specialized-timetable-recognition.md)。 |
| `config/ocr_engines.json` | 联合解析签名、离线资源打包与校验 | 当前引擎描述由 `core/ocr_engines.py` 定义，生产运行由 `app/bootstrap.py` 与 `schedule_core` 初始化本地 PaddleOCR。JSON 中的实验引擎仅是登记，不会因为修改 `default_engine` 就切换运行实现。 |
| `config/ocr_models.json` | `tools/prepare_offline_resources.py`、联合解析签名 | 构建准备工具读取模型来源、归档哈希和文件清单；运行时按离线清单校验本地资源。仅在明确执行下载准备命令时联网，不是运行时模型下载开关。 |
| `config/reference_library.json` | `tools/precache_reference_library.py`；另有 `app/bootstrap.py` 读取辅助函数 | 对应历史春季参考库，70 份/35 组是历史登记范围，不是每次导入的数量上限。默认相对路径只是本机配置占位，真实材料须在版本库外。 |
| `config/reference_library_samples.json` | 样本登记与审计映射 | 保留历史样本标识和哈希，不参与生产课表解析；历史 `accepted` 分类不是当前质量结论或人工真值。 |
| `resources/offline_manifest.json` | `app/offline_resources.py`、构建检查 | 校验配置与模型文件的大小和哈希；不能单独修改清单来掩盖资源不一致。 |

`core/signature.py` 将上述前五个配置文件的原始字节纳入联合签名。因此修改描述字段也会让旧解析结果、缓存与复核依据失效。本次文档核查补充消费边界，保留这些 JSON 与离线清单字节；不在并行识别验证期间更换配置或签名。

## 学期设置

用户设置保存在 `%LOCALAPPDATA%\Konggu\settings\calendar.json`。`app/services/calendar_settings.py` 校验周一日期及 1—30 周，保存时原子替换，并更新当前进程使用的学期环境变量。更改设置后，旧结果不能继续作为同一学期的正式导出依据。

用户设置只提供日期换算条件，不能补足课表未覆盖的周次；共同完整工作周由 `core/timetable_coverage.py` 根据已提供原件确定。

## 本地数据生命周期

- SQLite 默认路径为 `%LOCALAPPDATA%\Konggu\data\state.sqlite3`。任务请求和结果快照不保存源绝对路径；活动任务的 `job_files` 暂存路径，进入完成、失败或取消终态后清除，启动时也清除被标为中断的任务路径。
- 当前进程用内存映射支持原文核对；结束进程后该映射消失。程序没有跨重启 persisted-scope 授权恢复机制，恢复历史结果不等于已重新取得原文件访问能力。
- `StateStore` 初始化时清理超过 30 天的任务与修正，并执行 SQLite checkpoint 与整理。日期依任务更新时间或修正创建时间计算；不能解释为文件一生成就立即删除。
- `data.clear` 在有活动任务时拒绝执行；正常清理处理缓存及数据库任务、结果、问题、修正、审计，不删除用户选择的原 PDF，也不卸载模型或移除用户学期设置。
- 普通处理缓存过期清理由 `app/offline_resources.py` 管理，与任务数据库的生命周期分开；机器备份、隔离的损坏数据库和用户手工导出的成果不因此自动消失。

复核凭据按来源、成员、占用、问题、日历和解析签名匹配；人工修正还需要课程块标识匹配。完整依据见 [架构](full-iteration-implementation.md)和[质量门禁](状态与质量门禁.md)。
