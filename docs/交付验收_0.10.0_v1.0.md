# 空谷 0.10.0 逐项核验与部门空课表

## 试用步骤

1. 打开候选目录的 `试用空谷.cmd`，在「课表资料」导入「示例课表」中的四份 PDF。示例分属办公室和宣传部，每个部门各有一名成员和一对中英课表。
2. 首次试用的默认学期与示例一致，第一周周一为 2026-03-02，共 18 个教学周。点击「生成空课表」。
3. 在「课表核验」开始逐项核验。核对原件、课程名称、周次和节次，确认后进入下一项。随附示例共有 4 个带框核验项，覆盖第 1 周。实际业务中，选中课程可修正；缺课可补录，误识别的课程可删除。
4. 在「空课结果」切换到办公室或宣传部，点击时段查看本部门的有课和空闲人员。「成员课表」和「课程周视图」随部门切换。
5. 选择「导出空课表」，核对部门和人数，选择模板与当前周或全部覆盖周。「完整明细工作簿」可检查逐节名单、课程和来源；「青禾工作日周表」按周一至周五的大节排版，适合排班。某个时段内任意一节有课，这名成员就不会出现在该大节的空闲名单中。

## 本地交付物

候选目录为 `build/candidates/0.10.0-trial-20261122`。在 Windows 10/11 x64 上可选择 `试用空谷.cmd` 或 `Konggu_0.10.0_x64-setup.exe`。试用脚本从同目录的 `portable` 启动，将任务、OCR 缓存和浏览器配置保存在 `trial-data`。本次在本机通过该入口启动，观察到原生窗口、独立配置与识别进程。

安装器共 539620009 字节，SHA-256 为 `3d1cf717632988f31b8d133ef88ab8abd8494652ceba08a735f74f484772ebee`。42 项包检查通过，解包后的识别程序哈希与双部门端到端验收程序一致。另一台电脑及本版安装、升级尚待实测。

## 验证记录

- 将两部门的四份文字版合成 PDF 交给冻结程序实际解析。确认前导出被阻止，6 项逐一确认后恢复为可导出。同一时段在两个部门分别显示空闲与有课。另取一份单侧课表检查，缺件仍阻止正式导出。
- 重新打开两个单周 Excel，办公室完整明细工作簿共 11 个工作表，宣传部青禾周表共 1 个工作表。两个导出中均只包含所选部门的成员。四份试用 PDF 与验收输入逐一校验 SHA-256。
- 以带坐标的四份合成课表在 Chrome 验证预览和切换。原页实际显示框，8 条占用对应 4 个核验项。全部确认后从界面切换办公室和宣传部，核对结果、成员课表与周视图，再生成宣传部的两种单周 Excel。此轮使用冻结程序处理业务，通过桥接传入文件选择结果。两个工作簿均已重开并检查成员归属。
- 用真实配对原件在本地检查核验队列，342 条占用记录归入 159 个核验项，每条记录均可追溯到队列中的一项。这里核对的是识别记录与核验项的对应关系。
- 项目测试共通过 750 项 Python、9 项 Node 和 3 项 Rust 检查。冻结程序隔离验收覆盖资源恢复、本地图片 OCR、逐项确认和 Excel 导出。
- 在解包程序的真实 Windows 窗口中，用文件选择器导入随附的四份 PDF，生成批次并逐项点击「确认」。四个课程框均位于 PDF 区域内，核验进度从 0/4 变为 4/4。通过部门下拉框和系统「另存为」分别保存办公室的完整工作簿、宣传部的青禾工作日周表。复查两个工作簿共 11 个和 1 个工作表，均为第 1 周且仅含目标部门。实物保存在候选目录的 `导出示例`。
